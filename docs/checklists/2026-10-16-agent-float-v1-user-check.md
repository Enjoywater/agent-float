# Agent Float v1 — 사용자 확인 체크리스트

구현 중 화면이 잠겨 있었거나, 사람 손·시스템 설정 변경이 필요해 자동으로 확인하지 못한 항목. 결과는 설계 문서 5장의 "사용자 확인 대기" 행에 반영.

2026-10-19에 화면을 직접 조작해 확인한 결과는 항목마다 "확인함 (2026-10-19, 화면 조작)" 줄로 적음. 아직 사람이 봐야 하는 항목
- 승인 창·설정: 1·2·3 (Ghostty 제어 승인), 31·32 (손쉬운 사용 설정), 34·35 (로그인 항목)
- 새 앱·새 탭이 필요해 하지 않음: 7 Terminal.app, 8 Cursor, 10 `claude --bg` attach, 14 Orca 직접 탭 이동, 24 전체화면
- 만들기 어려움: 5 같은 제목 탭 (단위 테스트로만 확인)
- 취향: 21의 아래쪽 펼침 모습, 28 시안 비교, 29 움직임 느낌, 30 요약 줄 정렬
- 합성 입력의 한계: 18 실제 마우스로 끌 때 첫 움직임 반응, 26 NEW가 켜진 채 요약 줄 끌기, 9·13의 경고음 소리
- v1.2 답장 (2026-10-23): 41~45 모두 사람 손이 필요함 — 실제 입력기·실제 마우스·승인 창 거절. 화면 모양은 디버그 환경 변수로 띄워 캡처로 확인함

### 준비
- 화면 잠금 해제 후 `make run`(또는 `open "build/Agent Float.app"`)으로 실행. 확인이 끝나면 메뉴의 `Agent Float 종료`
- 로그를 같이 보려면 `AGENT_FLOAT_DEBUG=1 "build/Agent Float.app/Contents/MacOS/AgentFloat"` 로 실행
  - 이 방식은 Ghostty 셸에서 띄우면 승인 창이 Ghostty 몫으로 처리되어 뜨지 않음
  - 승인 창 흐름(아래 1번)을 보려면 `open`으로 실행
- 볼 로그: `navigate ok|failed|unconfirmed front=…`, `open application failed`, `focus watch on|off|checked|failed bundle=… next=… suspended=…|resumed` (v1.1 전에는 `ghostty watch …`), `marked seen` (fix round 1)

### Ghostty 자동화 권한과 이동
1. 첫 승인 창 (TCC)
   - 할 일: 다른 앱을 앞에 둔 채 Ghostty 세션 줄 클릭
   - 기대: "Agent Float이(가) Ghostty을(를) 제어하려고 합니다" 승인 창. 안내 문구 `세션이 열린 터미널 탭으로 이동하려면 그 터미널을 제어할 권한이 필요합니다.` 표시 (v1.1에서 터미널 공통 문구로 바뀜). 허용
   - 주의: NEW가 있는 동안 Ghostty가 맨 앞이면, 클릭하지 않아도 감시가 먼저 이 창을 띄울 수 있음
   - 주의: ad-hoc 서명이라 다시 빌드할 때마다 다시 물을 수 있음
   - 2026-10-19: 다시 빌드한 앱의 첫 Ghostty 이동이 클릭 뒤 3.5초 걸렸고(이후는 0.5초 안팎) 그 사이 커서가 움직임 → 승인 창에 사용자가 답했을 수 있으나 화면으로 못 봄. 승인 창이 떴는지는 사용자 확인
2. 승인 창에 30초 넘게 답하지 않기
   - 기대: 경고음, NEW 유지, `pgrep osascript`가 비어 있음(종료됨)
   - 답한 뒤 다시 클릭하면 이동함
3. 권한을 거절한 경우 (fix round 1, R38)
   - 기대: Ghostty 줄 클릭이 경고음만 냄
   - 기대: NEW가 있고 Ghostty가 앞일 때 직접 선택 감시는 한 번 실패한 뒤 멈춤 (로그 `ghostty watch failed … suspended=true`, 이후 `osascript`가 더 뜨지 않음)
   - 복구: 시스템 설정 > 개인정보 보호 및 보안 > 자동화 > Agent Float > Ghostty 켜기
   - 복구 뒤: 아무 세션 줄로 한 번 이동에 성공하면 감시가 다시 켜짐 (`ghostty watch resumed`). 앱을 다시 켜도 됨
4. Ghostty 이동 (Step 2)

   - 기대: Ghostty가 앞으로 오고 그 탭이 선택되며 그 줄의 NEW 해제
   - 실패 모습: 탭은 골라졌는데 Ghostty가 1초 안에 앞에 오지 않으면 경고음 + NEW 유지 (로그 `navigate unconfirmed front=…`)

5. 같은 제목의 Ghostty 탭이 여럿일 때
   - 기대: 같은 폴더의 탭으로 가고, 그래도 같으면 목록 첫 탭으로 감

### 창 동작·끌기·위치 (Task 9·10)
18. 끌기
   - 접힌 알약은 어디서든, 펼친 패널은 요약 줄에서 끌림. 다른 앱을 쓰는 중에도 첫 클릭에 바로 끌림
   - 끄는 중 펼침·접힘이 안 일어남
   - 펼친 채 옮긴 뒤 접히면 옮긴 자리에서 알약이 됨
   - 확인함 (2026-10-19, 화면 조작): 합성 입력으로 모두 기대대로. 다른 앱(브라우저)이 앞일 때 첫 누름에 끌림. 펼친 채 옮긴 뒤 접으니 옮긴 자리의 오른쪽 끝에 맞춰 알약이 됨. 합성 입력에서는 끌기가 시작되기까지 약 0.5초가 걸려 그 사이 움직임은 반영 안 됨 → 실제 마우스의 첫 움직임 반응은 사용자 확인
19. 눌렀다가 끌기 (R35)
   - 접힌 알약을 누른 채 바로 끌면 펼쳐지지 않고 옮겨짐
   - 누른 채 0.15초 이상 가만히 있어도 펼쳐지지 않음
   - 손을 뗀 뒤 커서가 알약 위에 있으면 hover로 펼쳐짐
   - 확인함 (2026-10-19, 화면 조작): 0.6초 눌러도 안 펼쳐짐, 떼고 0.16초 뒤 펼쳐짐. 누른 채 바로 끌면 펼쳐지지 않고 옮겨짐
20. 위치 복원

21. 화면 끝 처리

   - 확인함 (2026-10-19, 화면 조작): 주 화면 오른쪽에는 다른 모니터가 붙어 있어 오른쪽 모니터의 바깥 끝에서 확인: 끝 너머(X 3814~4094)에 두고 접으니 알약이 안쪽 끝(3893~4000)에 붙음
   - 참고: 주 화면 아래 끝까지 끌면 설치된 창 관리 앱 Magnet이 화면의 1/3 칸 위치로 옮김. 앱 결함 아님(설계 7장). 거슬림 여부는 사용자 판단
22. 포커스 유지
