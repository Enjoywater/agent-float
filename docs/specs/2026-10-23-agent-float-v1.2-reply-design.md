- 바탕: `2026-10-16-agent-float-design.md`(이하 "v1 설계") 7장 로드맵의 "플로팅에서 특정 세션에 간단한 메시지 보내기 **[사용자]**"

---

## 1. 의도

대기 줄(`ASK`)이 보여도 무엇을 묻는지 몰라 결국 터미널에 들어가 확인하고 답해 왔다. 사용자가 짚은 순간은 두 가지다 **[사용자]**:

- 질문 창(AskUserQuestion)으로 답을 기다릴 때
- "다음 작업 진행할까요?"처럼 본문으로 묻고 멈췄을 때

**들어가지 않고 그 자리에서 바로 답하고 싶다 [사용자]**. 질문 내용만 보여 주는 것으로는 부족하다고 사용자가 답함.

성공의 모습: 펼친 패널에서 대기 줄을 누르면 질문이 보이고, 고르거나 써서 보내면 그 세션이 다시 움직인다. 터미널로 가는 일은 플로팅이 확실히 보낼 수 없을 때뿐이다.

## 2. 목표 / 비목표 / 실패 조건

### 목표
1. 대기 세션의 질문 내용을 패널에서 읽음 — 질문 창은 질문·선택지·설명까지, 본문 질문은 마지막 답변 끝부분 **[사용자]**
2. 패널에서 답을 보냄 — 질문 창은 선택지 고르기·직접 쓰기·질문 여러 개, 본문 질문은 직접 쓰기 **[사용자]**
   - 실제 사용 비율(최근 transcript의 질문 창 답 115개): 선택지 83(72%), 직접 씀 32(28%). 질문이 2개 이상인 질문 창 27회 → 셋 다 1급 기능
   - 질문 창 호출 69회 중 여러 개 고르기 4회, 미리보기(`preview`) 선택지 0회
3. 보내는 길은 그 세션의 터미널에 키를 대신 입력하는 것. 지원 터미널: **Ghostty · Orca · tmux** **[판단]**
4. 답장 화면 배치 3종을 설정에서 고름. **기본값은 C(패널이 답장 화면으로 바뀜)** **[사용자]**
5. Toss·Apple·Spotify 수준의 꼼꼼한 UI·UX **[사용자]** — 이 문서의 4.6~4.8 수치와 시안이 기준

### 비목표
- 승인 창(권한 다이얼로그)에 답하기 — 사용자는 모든 대화형 세션을 권한 확인 없이 실행해 드묾(v1 설계 3장). 내용만 보여 주고 "승인은 터미널에서" **[판단]**
- Terminal.app · iTerm2 · Cursor · VS Code · 그 밖의 앱으로 보내기 — 보기만 하고 이동 **[판단]**. Terminal.app·iTerm2는 후속 후보(7장)
- 새 대화 시작, 대기 중이 아닌 세션에 메시지 보내기, 슬래시 명령 보내기
- 답 보내기를 되돌리기 (터미널에 들어간 키는 되돌릴 수 없음 → 막는 쪽으로 설계)
- Claude Code의 세션 간 메시지 통로(`messagingSocketPath`) 사용 — 받는 쪽에 "다른 세션이 보낸 메시지"로 들어가 내 답으로 취급되지 않고, 질문 창·승인 창에도 답할 수 없음(5장)

### 실패 조건 (동작은 해도 실패로 보는 것)
- **내 의도와 다른 답이 보내짐 — 절대 안 됨 [사용자]**. 이 문서의 모든 안전 장치는 이 한 줄에서 나온다. 다음은 모두 여기에 해당:
  - 다른 세션·다른 탭·다른 pane에 보냄
  - 고른 것과 다른 선택지가 선택됨, 직접 쓴 글에 다른 글자가 섞임(터미널에 쓰다 만 글, 숫자 키가 글자로 들어감 등)
  - 화면에서 보던 것과 다른 질문(그 사이 바뀐 질문)에 답이 들어감
  - 답이 반쯤 들어간 채 멈췄는데 사용자가 모름
- **확인할 수 없는 상황에서 보냄** — 하나라도 확인 못 하면 보내지 않고 이동만 **[사용자]**
- 답장 화면 밖에서 포커스를 뺏음 (v1 설계 2장 실패 조건 그대로. 답장 화면은 4.7의 예외)
- 쓰다 만 답이 사라짐
- 보낼 수 없는 세션인데 다 쓰고 나서야 알려 줌

## 3. 제약

- v1 설계 3장 그대로 (macOS 26.4, Apple Silicon, 사용자 본인 머신, 서드파티 의존성 없음)
- **회사·개인 정보 절대 금지 [사용자]**: 코드·테스트·fixture·문서·시안·커밋 메시지·인증서 이름 어디에도 회사 이름, 사람 이름·이메일·계정명, 실제 세션 제목·폴더명, 실제 transcript 문장을 넣지 않음. 실측에서 본 실물은 형식만 따서 가상의 내용으로 다시 만든다. 각 커밋 전에 검사 grep 0건(v1.1 최종 검사와 같은 방식)
- Claude Code 2.1.309 기준. 질문 창의 키 동작·화면 모양은 공개 계약이 아님 → 버전이 바뀌면 깨질 수 있다는 전제로, 매 단계 화면을 읽어 확인(4.4)
- 터미널: Ghostty 1.3.1, Orca 1.4.237, tmux 3.6a
- 지금 떠 있는 세션 8개 중 Ghostty 3, Orca 5(그중 2개는 Orca 에이전트 팀용 tmux 안). Ghostty 3개는 한 창의 탭들 → 가려진 Ghostty 탭은 드문 경우가 아니라 흔한 경우
- Ghostty 화면 읽기는 손쉬운 사용(Accessibility) API뿐이고 각 창에서 **지금 선택된 탭만** 읽힘(5장). Agent Float에 손쉬운 사용 권한이 새로 필요

## 4. 결정된 사항

### 4.1 범위 — 무엇에 답할 수 있나

| 대기 유형 (v1 `WaitReason`) | 패널 동작 |
|---|---|
| 질문 창 `question` | 읽기 + 답하기 (선택지 하나, 여러 개 고르기, 직접 쓰기, 질문 여러 개) |
| 본문 질문 `bodyQuestion` | 읽기 + 답하기 (직접 쓰기) |
| 승인 대기 `permission` | 읽기만. 도구 이름과 명령을 고정폭 상자로 보여 주고 "승인은 터미널에서 해 주세요" |
| 그 밖(`worker`·`sandbox`·`dialog`·알 수 없음) | 지금처럼 줄 클릭 = 이동 (답장 화면 없음) |

| 터미널 (v1 `TerminalLocator`) | 보내기 | 화면 읽기 |
|---|---|---|
| tmux `.tmux` (Orca 팀 tmux 포함) | `send-keys -t <pane>` | `capture-pane -p -t <pane>` |
| Orca `.orca` | `orca terminal send --terminal <handle>` | `orca terminal read --terminal <handle> --screen --json` (`draft` 필드 포함) |
| Ghostty `.ghostty` | `input text … to <terminal>` + `send key … to <terminal>` | 손쉬운 사용 API로 그 창의 텍스트 영역 값 — **그 탭이 선택돼 있을 때만** |
| Terminal.app·iTerm2·앱 폴백·백그라운드·none | 없음 → 읽기만 | — |

- **Ghostty 가려진 탭**: 앱을 앞으로 올리지 않고 그 창 안에서 탭만 바꿔(`select tab`) 화면을 읽을 수 있는지 먼저 실측한다(6장 스파이크 S3). 된다면 보내기 직전에만 탭을 바꾸고, 보낸 뒤 원래 선택 탭으로 되돌린다. 안 되면 가려진 탭은 읽기만 **[사용자: 확인 못 하면 이동만]**
  - 결과 (R62): 탭을 바꾸지 않음. 손쉬운 사용 API가 지금 데스크탑에 보이는 창만 읽어 탭을 바꿔도 다른 데스크탑의 창은 못 읽고, 사용자의 터미널 상태를 바꾸는 부작용이 큼 → 지금 보이는 창의 선택된 탭이고 터미널이 하나일 때만 보내고 나머지는 보기만
- **Ghostty 대상 지정은 이동보다 엄격**: v1 이동은 제목이 같은 탭이 여럿이면 첫 탭으로 가지만(v1 설계 4.4), 보내기는 제목+작업 폴더로 **정확히 하나**일 때만. 둘 이상이면 읽기만 **[판단]**
- Ghostty 탭 안이 분할(split)되어 텍스트 영역이 여럿이면, 그 터미널과 영역의 짝을 확실히 알 수 있을 때만 보냄. 모르면 읽기만 **[판단]**

### 4.2 질문 내용 읽기

transcript 끝부분(v1 `TranscriptReader`의 꼬리 창)에서 읽는다. 전체 파싱 금지는 v1과 같음.

- **질문 창**: 가장 최근의 `AskUserQuestion` `tool_use` 중 짝이 되는 `tool_result`가 아직 없는 것. 입력 형식(실물 확인):
  `{questions: [{question, header, multiSelect, options: [{label, description, preview?}]}]}`
  - 질문 식별자 = `tool_use.id`. 보내기 직전 확인(4.4 G1)과 보낸 뒤 확인(G4)이 이 값을 기준으로 함
  - `preview`가 있는 선택지는 Claude Code가 다른 배치(미리보기 옆 배치)로 그리고 키 동작도 다름(5장). 실제 사용 0회라 v1.2에서는 **보기만** — 미리보기 내용은 보여 주지 않고 "미리보기가 있는 질문은 터미널에서 답해 주세요" **[판단]**
- **본문 질문**: 마지막 assistant 텍스트(v1의 `lastAssistantText`)와 그 레코드의 `uuid`. 질문 식별자 = 그 `uuid`
- **승인 대기**: 짝 없는 마지막 `tool_use`의 도구 이름과 입력 요약(Bash는 `command`)
- 꼬리 창(256KB) 안에 질문이 없으면(아주 긴 질문 뒤 많은 기록 등) 읽기 실패 → 줄 클릭은 지금처럼 이동 **[판단]**
- 표시용 다듬기: 선택지 라벨 끝의 ` (Recommended)`는 떼고 **추천** 배지로 보여 줌. 보낸 뒤 확인(G4)은 **원래 라벨 문자열**로 비교 **[판단]**

### 4.3 보내는 방법 — 터미널에 키 입력

- 질문 창: 선택지는 화면 순서대로의 키 조작(숫자 키 또는 화살표 + Enter), 직접 쓰기는 "Type something." 항목으로 옮겨 글을 넣고 Enter. 질문 여러 개는 탭 이동과 마지막 "Submit". 정확한 키 순서는 **스파이크 S1에서 실측해 표로 고정**하고, 그 표가 코드의 기준이 됨
  - 직접 쓰기 항목의 번호를 "선택지 수 + 1"로 가정하지 않는다. 바이너리에 `__other__`("Type something.")와 `__chat__`("Chat about this") 두 추가 항목이 있음
- 본문 질문: 프롬프트 입력 칸에 글을 넣고 Enter
- 글자 입력은 붙여넣기 방식(Ghostty `input text`, Orca `--text`, tmux `send-keys -l`), Enter·화살표 같은 키는 키 이벤트(Ghostty `send key`, tmux `send-keys Enter`, Orca는 S2에서 확인)
- **절대 보내지 않는 키**: Esc, Ctrl+C, Ctrl+D, Ctrl+U 등 지우기·취소 키. 질문 창의 Esc는 질문 자체를 거절하고, 빈 프롬프트의 Ctrl+C·Esc Esc는 종료·되감기 메뉴를 염 → "쓰다 만 글을 지우고 보내기"는 하지 않고 보내지 않음으로 끝냄 **[판단]**
- 여러 줄 글: 질문 창의 직접 쓰기 칸과 프롬프트가 줄바꿈을 그대로 받는지 S1에서 확인. 확인 전까지 패널 입력 칸은 한 줄만 허용(Shift+⏎ 막음) **[판단]**

### 4.4 안전 확인 — 의도와 다른 답을 막는 단계 **[사용자: 절대 금지 / 판단: 단계]**

**미리 (답장 화면을 열 때, 쓰기 전)** — G0 보낼 수 있는지
- 4.1 표로 보낼 수 있는 세션인지, 대상이 하나로 정해지는지, 화면을 읽을 수 있는지(Ghostty는 그 탭이 선택됐는지와 손쉬운 사용 권한)를 정함. 안 되면 처음부터 "보기만" 화면(시안 10)
- 열려 있는 동안 상태가 바뀌면 다시 판정 (예: 사용자가 그 Ghostty 탭을 골라 보이게 되면 보낼 수 있게 바뀜)

**보내기를 누른 뒤** — 하나라도 실패하면 거기서 멈춘다. G1·G2에서 멈추면 **아무 키도 보내지 않은 것**, G3 도중 멈추면 **일부 키가 들어갔을 수 있음**

| 단계 | 확인하는 것 | 실패 시 |
|---|---|---|
| G1 같은 질문 | 표시 상태가 아직 대기이고 사유가 같음(질문 창은 원본 `waiting`·`input needed`, 본문 질문은 원본 `idle`·`shell` + v1 질문 판정). transcript의 질문 식별자(4.2)가 화면에 띄운 것과 같고, 그 뒤로 `tool_result`(질문 창)나 사용자 입력(본문 질문)이 없음 | 이미 답함 / 질문 바뀜 / 세션 끝남 → 보내지 않음 |
| G2 화면 | 터미널 화면에 그 질문 창이 떠 있음(질문 문장 일부로 대조), 커서 위치를 앎, 직접 쓰기 칸·프롬프트 입력 칸이 비어 있음. Orca는 자체 입력창(`draft`)도 비어 있음 | 쓰던 글 있음 / 화면이 예상과 다름 / 화면 못 읽음 → 보내지 않음 |
| G3 입력 | S1 표대로 키를 한 단계씩 보내고, 단계마다 화면을 다시 읽어 예상한 모습인지 확인 | 다르면 그 자리에서 멈춤 → "보내다 멈췄어요" |
| G4 기록 | 정해진 시간(빌더 재량, 출발점 5초) 안에 transcript에 답이 기록되고, 그 답이 보낸 것과 같음 — 질문 창은 `toolUseResult.answers[질문] == 원래 라벨(여러 개는 모든 라벨) 또는 직접 쓴 글`, 본문 질문은 다음 사용자 메시지 내용 == 보낸 글 | 시간 초과 / 다름 → "기록된 답이 보낸 답과 달라요" |

- G2의 "비어 있음" 판정이 애매하면(입력 칸의 안내 문구와 쓰던 글을 구분 못 함 등) 비어 있지 않은 것으로 본다 — 의심스러우면 보내지 않음
- 자동 재시도 없음. G3 이후 실패는 사람이 터미널에서 확인해야 함
- 같은 세션에 동시에 두 번 보내지 않음(보내는 중에는 화면이 잠김, 시안 6)

### 4.5 화면 — 배치 **[사용자: 3종 설정, 기본 C]**

| 배치 | 내용 | 비고 |
|---|---|---|

### 4.7 상호작용 **[판단]**

- **열기**: 답할 수 있거나 읽을 수 있는 대기 줄(4.1)을 클릭하면 답장 화면. ⌘+클릭은 지금처럼 바로 이동. 그 밖의 줄은 v1과 같음. → v1 설계 4.7 "줄 클릭 → 이동"을 대기 줄에 한해 바꿈
- **키보드 포커스 — v1 원칙의 예외**: 답장 화면이 열리면 패널이 키 입력을 받는다(사용자가 그 줄을 눌러 답하려는 의도를 밝혔으므로). 앱 자체는 활성화하지 않음(비활성 패널 유지). 보내기 성공·‹·esc로 닫으면 **열기 전 앱이 다시 키 입력을 받아야 함**. 목록·알약·hover·끌기는 v1처럼 포커스를 가져가지 않음
- **키**

| 키 | 동작 |
|---|---|
| 1~9 | 그 번호의 선택지를 고름(보내지 않음). 입력 칸에 커서가 있을 때는 글자 |
| ⏎ | 보내기 (질문 여러 개면 다음 → 마지막은 답 확인 → 보내기). 선택도 글도 없으면 아무 일 없음 |
| ⏎ (한글 조합 중) | 조합만 확정. 보내지 않음 (`hasMarkedText` 확인) |
| Tab | 입력 칸에 들어가고 나옴. 선택지는 숫자 키로 고름 (구현 중 결정: 선택지마다 포커스 테두리를 두지 않고 숫자 키로 대신함) |
| esc | 입력 칸에서는 커서만 빠짐, 그다음 esc는 목록으로(쓴 답 유지) |
| ⌘+클릭 (목록 줄) | 바로 이동 |

- 여러 개 고르기(`multiSelect`)는 번호 키가 켜고 끄기, 선택지 앞 표시는 체크 상자 모양
- **쓰다 만 답**: 질문 식별자별로 메모리에 보관(앱을 끄면 사라짐). 다른 줄로 가거나 접혀도 남고, 다시 열면 그대로. 질문이 바뀌거나 세션이 대기를 벗어나면 버림
- **접힘**: 답장 화면이 열려 있는 동안은 마우스가 벗어나도 접히지 않음. 다른 앱을 클릭해 패널이 키 입력을 잃고 마우스도 밖에 있으면 평소 지연 뒤 접히고, 다음에 펼치면 **목록**으로 열림(쓴 답은 "작성 중"으로 남음)
- **열려 있는 동안 바뀜**: 이미 답함·세션 끝남 → 띠 + 1.2초 뒤 목록. 질문 바뀜 → 띠 + 새 질문. 보낼 수 있음 ↔ 보기만이 바뀌면 띠와 버튼만 바뀌고 쓴 답은 유지
  - 단, **이 패널이 키를 한 번이라도 보낸 뒤(G3 시작 이후)에는 저절로 닫는 규칙이 적용되지 않음**. G4에서 틀린 답이 기록되면 세션은 곧 대기를 벗어나 "이미 답함"처럼 보이지만, 이때는 실패 화면이 이김
- **신호**: 보내기 성공 뒤 대기 해소는 v1 규칙 그대로(세션 상태가 바뀌면 `ASK`가 꺼짐). 답장 화면을 여는 것만으로는 `ASK`가 꺼지지 않음 — v1의 "이동·클릭만으로는 안 꺼짐 **[사용자]**"과 같은 원칙
- **보내기 실패 표시** — "반쯤 들어간 채 멈췄는데 사용자가 모름"을 막는 장치 **[판단]**
  - 켜지는 때: G3에서 멈춤, G4에서 다름·시간 초과. 세션 단위
  - 꺼지는 때: 사용자가 확인했을 때만 — 그 세션의 실패 화면에서 "닫기"·"터미널에서 열기"를 누르거나, 그 세션 줄을 ⌘+클릭해 이동. 세션 상태가 바뀌어도(대기 → 진행·완료) 꺼지지 않음. 세션 프로세스가 끝나면 목록에서 빠지며 같이 사라짐
  - 알약: 맨 앞에 빨간 점 + 개수 + 빨간 `FAIL` 꼬리 (`ASK`·`NEW`와 같은 규칙: 무엇인지는 글자가 말함). 테두리 빛은 `ASK`·`NEW`·`FAIL` 중 하나라도 있으면 돎
  - 목록: 맨 위에 "확인 필요 N" 묶음(머리 빨강). 표시가 켜진 세션은 원래 상태 묶음에서 빠져 여기에만 나옴. 점은 실제 상태 색 그대로, 2행 사유 자리에 빨간 "보내기 실패"
  - 그 줄을 누르면 세션 상태와 상관없이 실패 화면(시안 9: 멈춘 단계, 또는 보낸 답 / 기록된 답)이 열림
  - 앱을 끄면 사라짐(메모리 보관) — 다시 켤 때는 실패 여부를 알 수 없음

### 4.9 권한

- Ghostty 화면 읽기에 손쉬운 사용 권한이 필요. 처음 Ghostty 세션의 답장 화면을 열 때 요청(`AXIsProcessTrustedWithOptions`). 거절·대기 중이면 Ghostty 세션은 "보기만" + "설정 열기" **[판단]**
- **서명 [사용자: 추천안 채택]**: ad-hoc 서명은 다시 빌드할 때마다 권한이 풀리므로, 로그인 키체인에 **로컬 전용 자체 서명 코드 서명 인증서**를 하나 만들어 그것으로 서명한다. 한 번 허용하면 다시 빌드해도 손쉬운 사용·자동화 권한이 유지됨
  - 인증서 이름은 앱 이름만 씀(예: `Agent Float Local Signing`). 이메일·조직·사람 이름 등 다른 필드는 비움 **[사용자: 회사·개인 정보 금지]**
  - 키체인에 이미 있는 다른 인증서(회사 배포용·개인 개발용)는 쓰지 않음 **[사용자]**
  - 신뢰 설정·개인 키 접근 허용에서 macOS 확인 창이 한 번 뜰 수 있음 → 사용자가 직접 허용
  - Makefile은 그 인증서가 있으면 그것으로, 없으면 지금처럼 ad-hoc으로 서명하고 경고를 출력(다른 머신에서도 빌드는 되게) **[판단]**

## 6. 빌더 재량과 먼저 할 실측

**계획의 첫 Task는 서명 준비(4.9)와 실측(스파이크)** 이고, 실측 결과로 4.3의 키 표와 4.4의 화면 판정 규칙을 고정한다. 실측에서 얻은 화면 캡처를 테스트 fixture로 쓸 때는 3장의 금지 규칙대로 가상의 내용으로 다시 만든다. 구현 순서는 tmux → Orca → Ghostty(실측 결과가 가장 불확실한 순서) **[판단]**. 시험 세션은 v1.1과 같은 방식(haiku, 이미 신뢰한 폴더, 끝나면 `/exit`, 이 세션의 `CLAUDE_CODE_*` 환경을 비운 셸). 사용자의 실제 세션에는 보내지 않는다.

| 스파이크 | 확인할 것 | 결과가 안 좋을 때 |
|---|---|---|
| S1 질문 창·프롬프트 (tmux 위에서) | 기본·미리보기 배치, 하나·여러 개 고르기, 직접 쓰기, 질문 여러 개 각각의 키 순서와 단계별 화면 모양. 직접 쓰기 칸·프롬프트의 줄바꿈. 빈 프롬프트와 안내 문구·쓰던 글 구분. `tool_use`가 창이 뜰 때 이미 기록되는지 | 확실히 정할 수 없는 유형은 읽기만 |
| S2 Orca | `terminal send`로 숫자·Enter·화살표, `read --screen`이 질문 창을 그대로 보여 주는지, `draft`의 의미 | 안 되는 키가 필요한 유형은 Orca에서 읽기만 |
| S3 Ghostty | Agent Float 자신의 손쉬운 사용 권한으로 화면 읽기, 가려진 탭에 `input text`·`send key`가 들어가는지, `select tab`이 앱을 앞으로 올리지 않는지, 창·탭·분할과 텍스트 영역의 짝 | 가려진 탭은 읽기만, 분할은 읽기만 |
| S4 패널 키 입력 | 비활성 패널이 키 창이 되어 한글 입력·조합이 되는지, 닫은 뒤 이전 앱이 키 입력을 되찾는지 | 이전 앱 되찾기가 안 되면 닫을 때 그 앱을 다시 활성화. 앱을 활성화해야만 한글 입력이 되면 **답장 화면이 열려 있는 동안만** 활성화하고 닫을 때 이전 앱을 다시 활성화 **[판단]** |

**[빌더]** 에게 맡기는 것
- 코드 구조와 이름. 참고 형태: Core에 질문 모델(질문 창·본문 질문·승인 대기), transcript 꼬리에서 그 모델 읽기, 터미널별 보내기·화면 읽기 프로토콜(v1 `TerminalNavigator`처럼 등록 방식), 질문+답 → 키 단계·단계별 기대 화면을 만드는 계획기, G1~G4를 돌리는 전달기. 계획기·화면 판정·대조는 가짜 실행기와 화면 fixture로 단위 테스트
- G4 대기 시간, 단계별 화면 재확인 간격과 시간 제한
- 마지막 답변 "끝부분"의 길이(출발점: 마지막 12줄 또는 600자), 마크다운 처리 수준(굵게·목록·코드 정도)

- B 카드의 정확한 위치 계산
