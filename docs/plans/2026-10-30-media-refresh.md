# 배지 적용 버전 미디어 확보 계획

작성일: 2026-10-30. 현재 상태: 촬영·미디어 교체 완료. 가상 시나리오와 촬영 도구로 GIF 11개를 교체했고, 접힌 알약 GIF 14개는 검토 후 유지했다. [실행 결과와 검수 기록](../checklists/2026-10-30-media-refresh-review.md)을 참고한다.

## 준비 결과

- `FakeProvider`에 고정 시나리오 9개와 Claude/Codex 선택을 추가했다. 가상 모드에서만 적용한다.
- 가상 모드의 실제 터미널 navigator·포커스 probe 연결을 비웠다. 기존 실제 세션 모드의 연결은 유지한다.
- `scripts/media/shots.json`에 GIF 25개의 설정·조작 순서·촬영 시간·출력 크기를 기록했다.
- [촬영 도구 사용법](../../scripts/media/README.md)과 가상 배경 HTML을 준비했다. 준비·검사와 실제 화면을 사용하는 명령을 구분했다.
- `build/media-refresh/Agent Float Media.app`을 release 빌드하고 서명을 검증했다. 번들 식별자는 `dev.enjoywater.agent-float.media`다. 설치된 앱을 교체하거나 실행 중인 앱을 종료하지 않았다.
- Swift 테스트 468개가 통과했다. 화면을 녹화하지 않고 생성한 테스트 영상으로 480×720·15fps GIF 변환을 확인했다.
- 추가·수정한 코드와 도구에서 일본어 가나·한자 문자열이 남아 있지 않은지 확인했다.
- 촬영 단계에서 화면 기록 권한, 내장 디스플레이, 배율·구도와 UI 조작을 확인했다.

촬영 종료 후 촬영용 앱과 가상 배경을 닫았다. 이후의 변환·문서 검수는 화면 입력 제어 없이 진행한다.

## 목표와 범위

현재 앱의 Claude/Codex 이름 배지가 README와 기능소개서에서도 일관되게 보이도록 한다. 최신 네이티브 앱을 가상 세션으로 실행해 촬영한다. HTML 데모나 정지 이미지를 움직여 앱 녹화처럼 만들지 않는다.

현재 `docs/media`에는 GIF 25개, 배지 미리보기 PNG 2개, 로고 PNG 1개가 있다. 우선 기능 GIF 11개를 교체한다. 상태·배경 GIF 14개는 전체 프레임을 확인한 뒤 배지 영역이 등장하거나 현재 모습과 달라진 경우 교체한다. 새 파일을 무조건 늘리기보다 기존 사용처와 파일명을 유지한다.

## 1. 촬영 전에 준비할 것

현재 저장소에는 완성된 녹화 스크립트가 없다. 다음 기능은 이미 있다.

- `AGENT_FLOAT_FAKE_SESSIONS`: 실제 세션 대신 가상 세션을 표시한다.
- `AGENT_FLOAT_APPEARANCE=light|dark`: 앱의 화면 모드를 고정한다.
- `AGENT_FLOAT_REPLY_PLACEMENT=panel|inline|card`: 답장 배치를 고정한다.
- `AGENT_FLOAT_FAKE_REPLY=delivered|hidden|accessibility|draft|stopped|mismatch`: 전송 결과를 재현한다.
- `AGENT_FLOAT_FAKE_REPLY_STAGE_DELAY`: 가상 전송 단계가 화면에 머무는 시간을 정한다.
- `AGENT_FLOAT_DEBUG=1`: 창 좌표를 기록하고 디버그 펼침·접힘 신호를 사용할 수 있다.

준비 전 `FakeProvider`는 행 번호로 에이전트와 상태를 배정해 질문 대기 행이 모두 Claude였다. 일반 가짜 세션 모드는 유지하되, 별도의 고정 촬영 시나리오에서 Codex 답장도 선택할 수 있도록 보완했다.

아래 촬영용 시나리오 선택을 구현했다. 실제 설정과 파일별 선택은 `scripts/media/shots.json`에 기록했다.

| 시나리오 | 고정할 내용 | 필요한 이유 |
|---|---|---|
| 혼합 목록 | Claude/Codex 각각 대기·진행·완료, 짧은 가상 제목·폴더 | 배지 두 종류와 터미널 아이콘을 한 장면에서 비교 |
| 질문 하나 | 에이전트 선택, 선택지 질문, 전송 성공 | Codex 배지와 답장 흐름을 함께 촬영 |
| 질문 여러 개 | 에이전트 선택, 질문 두 개, 확인·수정·전송 | 다중 질문 설명 유지 |
| 본문 질문 | 에이전트 선택, 짧은 본문, 직접 입력 | 본문과 에이전트 문맥 유지 |
| 승인 대기 | 에이전트 선택, 가상 도구·명령 | 보기만 지원하는 상태 촬영 |
| 전송 중단·불일치 | 에이전트와 결과 지정 | 보내지 않음과 FAIL을 구분 |
| 상태 전환 | 시작 상태·전환 시점 고정 | ASK·NEW가 녹화 도중 우연히 바뀌지 않게 함 |

시나리오는 실제 터미널·세션으로 이동하거나 입력하지 않아야 한다. 전송 성공 장면은 `FakeReplyBackend`의 표시 동작이며, 실제 전송 기능의 검증 자료로 취급하지 않는다. 실제 이동 장면이 필요하면 별도의 테스트 터미널과 가상 프로젝트로 촬영한다.

촬영용 앱은 별도 번들 식별자와 설정 저장소로 실행해 설치된 앱의 위치·배치 설정과 섞이지 않게 한다. 실제 세션을 읽는 provider와 실제 전송 backend가 연결되지 않았는지 촬영 전에 확인한다.

라이트·다크 한 쌍은 에이전트·제목·질문·조작 순서를 같게 한다. 단일 파일은 기존 테마를 먼저 유지하고, 반대 테마에서도 배지와 글자가 읽히는지 별도로 확인한다. 모든 GIF를 두 테마 파일로 증식시키지는 않는다.

## 3. 검토 후 유지하거나 교체할 14개

| 파일 묶음 | 개수 | 판정 기준 |
|---|---:|---|
| `state-{ask,running,new,unknown}-{light,dark}.gif` | 8 | 접힌 알약만 표시되고 현재 모습과 같으면 유지. 목록·답장으로 전환하는 프레임에 배지가 빠져 있으면 재촬영 |
| `bg-{light,dark,doc,sonoma,code,vivid}.gif` | 6 | 모든 프레임에서 현재 유리 효과·레이아웃과 같고 배지 영역이 없으면 유지. 구버전 목록이 보이면 같은 배경으로 재촬영 |

기존 `agent-identity-light.png`·`agent-identity-dark.png`는 현재 SwiftUI 배지 렌더링이므로 기본적으로 유지한다. 시나리오 준비 과정에서 배지 자체의 모습이 바뀌면 함께 다시 렌더링한다. `logo.png`는 유지한다.

Codex의 notes 직접 입력은 기존 미디어에 없는 장면이다. 1차 교체를 마친 뒤 별도 GIF 한 개를 추가할지 검토한다. 이 경우 README·소개서에 사용처와 설명을 함께 추가하고, Codex가 지원하지 않는 여러 개 고르기를 지원하는 것처럼 표현하지 않는다.

## 4. 촬영과 변환 기준

1. 먼저 대표 장면 세 개만 시험 촬영한다: 혼합 목록, Codex 선택지 답장, Codex 옆 카드. 글자 크기·배지 가독성·카드 경계·움직임을 확인한 후 나머지를 촬영한다.
2. 배경·디스플레이 배율·앱 위치·창 너비를 고정한다. 가상 제목과 폴더에는 `agent-float`, `sample-app` 등을 사용한다. 배경 예시의 문서·코드도 가상 내용으로 준비한다.
3. macOS 화면 기록 또는 로컬 녹화 도구로 실제 앱을 기록한다. 창 그림자와 펼침·카드의 최대 범위를 포함한 고정 영역을 잡고, 장면 도중 크롭 영역을 이동시키지 않는다.
4. 원본은 30fps 이상을 목표로 확보한 뒤 실제 fps를 검사하고, 문서용 GIF는 15fps로 변환한다. 기본 속도로 촬영하고, 짧게 만들기 위해 입력이나 전송 단계를 과도하게 가속하지 않는다.
5. 시작·끝 상태를 각각 약 1초 읽을 수 있게 남긴다. 키보드·마우스 커서는 필요한 동작에서만 화면 안에 둔다. 반복 재생 때의 마지막 → 첫 프레임 전환도 확인한다.
6. 설치된 `ffmpeg`·`ffprobe`를 사용해 변환·검사한다. 전용 팔레트를 생성해 글자와 유리 경계의 색 번짐을 줄인다. `gifski`는 현재 설치되어 있지 않으며 필수 의존성으로 추가하지 않는다.
7. 변환 후 README의 실제 표시 너비에서 배지가 읽히는지 확인한다. 파일 크기는 기존 파일 대비 증가하지 않는 것을 우선 목표로 하고, 가독성을 해치지 않는 범위에서 길이·fps·크롭을 조정한다.

현재 출력 크기는 hero 460×574, 선택지·본문·다중 질문·실패 화면 480×720, 줄 안 펼침 480×982, 옆 카드 720×680이다. 우선 이 크기를 유지하되 새 배지나 카드가 잘리면 필요한 만큼 조정하고 문서의 표시 크기도 확인한다. 상태·배경 GIF의 기존 크기는 유지한다.

## 5. 재현 자료와 원본 관리

구현 단계에서 다음 자료를 남긴다.

- `scripts/media/` 아래에 시나리오 실행·촬영·변환 절차와 환경 준비 방법을 둔다. 자동으로 하기 어려운 화면 조작은 순서와 종료 조건을 명시한다.
- 촬영 manifest에는 파일명, 소스 커밋, macOS 버전, 테마, 배경, 시나리오, 배치, 결과 모드, 크롭 좌표, 배율, 길이, fps, 출력 크기와 용량을 기록한다.
- 원본 영상과 변환 중간 파일은 `build/media-refresh/`에 보관한다. 이 경로는 기존 `.gitignore`의 `build/`에 포함되어 커밋되지 않는다.
- Git에는 최종 GIF·필요한 PNG·재현 스크립트·manifest·미디어 사용처 대조표를 남긴다. 원본을 장기 보관할 외부 위치는 아직 지정하지 않았으므로 업로드하지 않는다.
